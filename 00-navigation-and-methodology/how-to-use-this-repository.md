# How to Use This Repository

## If you are...

**New to Responsible AI** — start with [01-foundations/what-is-responsible-ai.md](../01-foundations/what-is-responsible-ai.md), then [01-foundations/responsible-ai-vs-ai-ethics.md](../01-foundations/responsible-ai-vs-ai-ethics.md), then [01-foundations/principles.md](../01-foundations/principles.md).

**Building a Gen AI or Agentic AI feature** — read the relevant technology section (06 or 07) alongside [02-ai-lifecycle/lifecycle-overview.md](../02-ai-lifecycle/lifecycle-overview.md) for the checkpoints you'll hit, and use [13-implementation-playbooks](../13-implementation-playbooks/) as your working checklist.

**Reviewing/approving an AI use case (governance role)** — go to [03-ai-governance](../03-ai-governance/) for process, [04-ai-assurance](../04-ai-assurance/) for what evidence to demand, and [10-regulations-and-standards](../10-regulations-and-standards/) for applicable obligations.

**In legal/compliance** — [10-regulations-and-standards](../10-regulations-and-standards/) is your primary section; cross-reference [11-sector-specific-ai](../11-sector-specific-ai/) for industry-specific obligations.

**Selecting tools/vendors** — [09-tools-and-frameworks](../09-tools-and-frameworks/) has the comparison matrices; [13-implementation-playbooks/vendor-third-party-ai-assessment.md](../13-implementation-playbooks/vendor-third-party-ai-assessment.md) has the assessment process.

**Investigating an incident or researching precedent** — [12-case-studies](../12-case-studies/), structured by failure type, each following a standard template so cases are comparable.

## Navigation principles

- **One topic, one file.** If you can't find something, check [knowledge-map.md](knowledge-map.md)'s section table before assuming it's missing.
- **Cross-links, not duplication.** Files reference each other rather than repeating content — follow the links rather than expecting every file to be self-contained.
- **Depth increases as you go deeper into a section.** Top-level files in each numbered folder are overviews; look for more specific files for implementation detail.

## Keeping this current

See [source-and-evidence-policy.md](source-and-evidence-policy.md) for how claims should be sourced, and the root [CONTRIBUTING.md](../CONTRIBUTING.md) for the update process. Regulatory and tooling content dates quickly — check the `_Last reviewed_` line at the top of any file in sections 09 and 10 before relying on it for a decision.
